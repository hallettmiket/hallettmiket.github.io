Biosharc: the lab's cluster nodes, from murmurent

For members of the Hallett lab at Western. Last checked against the cluster on 12 November 2026.

What it is. Biosharc is two compute nodes the lab owns inside Dusky, a SHARCNET cluster run by the Digital Research Alliance of Canada. Each node has 256 cores, 2.2 TB of memory and four NVIDIA L40S GPUs. Because the lab bought them, jobs charged to the lab's account run there with priority, a seven-day time limit and no caps. Nothing is installed on the cluster for this: murmurent submits over SSH from your laptop or from biodatsci.

Getting access

  1. An Alliance account. Apply at ccdb.alliancecan.ca with Mike's CCRI as sponsor. You get an Alliance user name (not your Western one).
  2. Membership of the lab's group. Ask Mike to add you to ctb-hallett on CCDB. That is what lets you use the biosharc partition. Without it the scheduler refuses the partition and murmurent tells you so.
  3. Log in once by password and put your key there, from your laptop and again from biodatsci, since each machine needs its own: 
    ssh-copy-id -i ~/.ssh/id_ed25519.pub <alliance-login>@dusky.sharcnet.ca
    Dusky asks for your Alliance password and nothing else. If ssh-copy-id says permission denied, the user name is wrong: it is your Alliance login, not your Western one.
  4. Tell murmurent, on each machine you submit from: 
    murmurent cluster add dusky --ssh-host <alliance-login>@dusky.sharcnet.ca
murmurent cluster test
    test logs in and confirms that you may charge the lab's account.

Running something

From inside the experiment folder of a murmurent project:

cd ~/repos/my_project/exp/3_fit
murmurent cluster submit --name fit --cores 16 --gpus 1 --memory 64G --time 6h -- python run_all.py
  • The folder is copied to your scratch space on Dusky. The job runs there, charged to ctb-hallett on the biosharc partition. You never have to type either.
  • Write results to $MURMURENT_OUT inside your script. That folder comes back to the experiment's append_only folder on the machine you submitted from, without overwriting anything already there.
  • A watcher in tmux asks the scheduler every two minutes. When the job ends it copies the results back, pulls the log, and posts one line to the project's Slack channel.
  • murmurent cluster status lists your cluster jobs; status <id> asks the scheduler about one; cancel <id> stops it; fetch <id> copies the results again.
  • Choose --time from an earlier run plus a margin. A job that runs out of time is lost work. Up to seven days is allowed.
  • Or ask the millwright: "run this experiment on biosharc with one GPU for six hours" does the same.

murmurent cluster usage prints your own figures for each tier. The file-count limit matters as much as the byte limit. The lab's copy of record stays in append_only on biodatsci; what sits on Dusky is a working copy.

Moving data

  • Large data goes directly between biodatsci and Dusky, never through a laptop: from biodatsci, murmurent cluster push <folder> '{scratch}/<folder>', or plain scp -r.
  • murmurent cluster pull '{project}/results/run7' ~/results/run7 brings things back without overwriting what is already there.
  • Copying large files within /project should be done logged in to Graham, not Dusky; the cluster's own banner asks for this.
  • Protected-tier data (patient-derived) does not go to the cluster unless the project's data agreement allows it. Ask before moving it.

Things to know

  • 7 December to 3 January: /home is read-only and /project unavailable on Dusky while the Graham data centre is worked on. Plan jobs around it.
  • The login node is shared. Run nothing heavy there; submit it.
  • The same two nodes also appear in the public gpu partition with a 12-hour limit and no priority. Always use biosharc; murmurent does.
  • The Alliance's usage website shows only the national clusters (Fir, Nibi, Narval, Rorqual), which the lab can use opportunistically under def-hallett-ab. Biosharc use does not appear there. Mike sees it with murmurent cluster scan.
  • Prefer Biosharc. Use Nibi or Fir only for what Biosharc cannot do: more than four GPUs, more than one node, or software only installed there.
  • Questions about the cluster itself: help@sharcnet.ca. Questions about access and the lab's account: Mike.
